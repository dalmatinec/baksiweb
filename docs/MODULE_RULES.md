# Правила для модулей (ботов в каталоге)

Чек-лист перед тем, как добавить бота в каталог или выпустить обновление модуля. Каждый пункт здесь появился
из реальной ошибки: внизу журнал найденных проблем, его пополняем при каждой новой.

## Одновременность

1. **Обработчики работают одновременно.** aiogram обрабатывает апдейты параллельно. Альбом из 5 фото — это
   5 сообщений в одну и ту же долю секунды, двойное нажатие — два колбэка.
2. **Нельзя «проверить, потом записать» без защиты.** Логика «SELECT нет записи → INSERT» ломается при двух
   одновременных вызовах. Варианты:
   - уникальный индекс + `INSERT ... ON CONFLICT DO UPDATE` / `INSERT OR IGNORE`, затем повторный `SELECT`;
   - транзакция `BEGIN IMMEDIATE`;
   - `asyncio.Lock` на ключ (пользователя, заявку). Для сообщений одного пользователя - замок на user_id.
3. **Счётчики и лимиты** (использования промокода, места, остатки) обновляются одним условным запросом:
   `UPDATE ... SET used = used + 1 WHERE used < max` и проверка `rowcount`.
4. **Тест на одновременность обязателен** для любой логики «одна запись на …»: `asyncio.gather` из нескольких
   одинаковых апдейтов, ожидаем ровно одну запись.

## Смена бота (клиент удалил бота и подключил новый токен)

5. **file_id привязан к боту.** Новый бот не может отправить картинку по file_id старого. Медиа храним на диске
   (в `DATA_DIR`), а file_id - только как кэш для конкретного bot_id, с повторной заливкой с диска.
6. **Новый бот не состоит в группах и каналах старого.** Ссылки на сообщения (`chat_id` + `message_id`), права админа
   и привязки групп надо восстановить. Платформа сама сбрасывает привязку группы (`/bind`). В манифесте модуля
   пишем `bot_change_hint`: что клиенту сделать. Платформа пришлёт ему это в хаб-бот и покажет в кабинете.
7. **Новый бот не может первым написать людям**, пока они не нажали у него /start (исполнители, подписчики).
   Это тоже пишем в `bot_change_hint`.

## Устойчивость

8. **Одна плохая группа или пользователь не должны ронять бота.** Каждую отправку оборачиваем:
   - `TelegramForbiddenError` - пометить и пропустить;
   - `TelegramBadRequest` - залогировать и пропустить;
   - `TelegramRetryAfter` - подождать и повторить.
9. **Массовые отправки** (рассылки) - с паузой между сообщениями, не быстрее ~20 в секунду.
10. **Память.** Лимит процесса задаётся `mem_mb` в манифесте, при превышении супервизор перезапустит бота.
    Не держать в памяти большие файлы и неограниченные словари: кэши чистить, на `dict` ставить предел.
11. **Остановка по SIGTERM.** Закрыть базу и сессию бота в `finally`.
12. **Падение при старте = цикл перезапусков.** Ошибки настройки (нет группы, нет данных) не должны валить процесс:
    бот работает и подсказывает владельцу, что сделать.

## Понятность для владельца бота

18. **Каждый ввод получает видимый ответ внизу чата.** Если бот удаляет сообщение админа (чтобы не мусорить), ответ
    «✅ Сохранено» или «⚠️ Не сохранено: причина» приходит новым сообщением, а не правкой старого где-то выше.
    Пока идёт обработка (загрузка картинки) - показывать «печатает…».

## Платформа

13. Все пути только через `DATA_DIR`, никаких файлов рядом с кодом.
14. После запуска - `baksi_kit.ready(bot)`. Привязка группы - `baksi_kit.bind_router()`.
15. Токены и личные данные не пишем в логи (платформа дополнительно вырезает токены).
16. Тексты и кнопки, которые владелец платформы может менять для всех, - через `baksi_kit.ui_text/ui_btn/ui_cols`
    и блок `ui` в манифесте. Своя правка клиента важнее настройки владельца.
17. Модуль должен работать и без платформы (обычный запуск с `.env`).
